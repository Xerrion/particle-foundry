# P1 / M1 / E03 browser contract evidence

**Status:** E03 browser contract validated on 27 September 2026. M1 and P1
remain incomplete. This slice defines bounded host behavior for a future owned
physical scene; no Rust CPU or GPU physics scene is promoted.

**Run source:** committed base `a9c9834251e68ebd8e8d51ff5bf0351ecd625603`
plus the E03 working-tree changes in this delivery. The final `mise run ci` run
completed with 451 TypeScript tests and 11 Rust tests, plus lint, both type checks,
production and WASM builds, generated-binding/catalogue freshness, browser
bootstrap with BrowserWebGpu device initialization, and docs validation. Its raw
local log is ignored `artifacts/e03-ci-final.log`. The smoke does not exercise
this mock-host session contract on a physical Rust scene.

[`session.ts`](../../web/src/engine-client/session.ts) preflights model,
execution, geometry, material IDs and boundaries before an owner is constructed.
It holds up to 64 copied commands per epoch and one in-flight batch, including
zero-tick flushing of paint while paused. Accepted physical time advances only
after the owner reports a valid completion. Reset allocates a new owner before
replacing the old one, aborts pending probes and ignores late callbacks. Rejected
batches fault the current epoch until reset; they are never retried implicitly.
The contract does not create a second ticking world.

The legacy browser path remains synchronous through
[`legacy-adapter.ts`](../../web/src/engine-client/legacy-adapter.ts).
[`canvas.ts`](../../web/src/engine-client/canvas.ts) chooses a context owner before
acquisition. The first [catalogue projection](../../web/scripts/project-engine-catalogue.ts)
derives carrier air, liquid water and fixed-wall stone IDs with SI density and
viscosity from the single authored definitions. Its ignored JSON output under
`web/generated/catalogue/` has a source SHA-256 and a freshness check. These
three inputs are candidate metadata, not validated fluid properties or a
supported GPU scene.

## Current verification

The [session tests](../../web/tests/app/engine-session.test.ts) exercise feature
rejection before allocation, bounded and atomic queueing, paused paint, in-flight
backpressure, reset, cancelled/stale probes, invalid owner completions and accepted
time. The [canvas test](../../web/tests/app/canvas-owner.test.ts) covers exclusive
context choice; the [projection test](../../web/tests/materials/engine-projection.test.ts)
compares the generated IDs and SI fields with the authored catalogue.

The final command results and source revision are recorded in
[the continuation handoff](../RESUME.md#e03-verification). Passing mock transport
tests does not establish a Rust command handler, GPU work completion, shader
ABI parity, save/load, numerical correctness or supported-scene promotion. Those
remain future gates.
