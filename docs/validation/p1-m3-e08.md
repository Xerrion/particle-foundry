Both seeds pass host and f32 validation. The [renderer](../../engine/crates/sim-gpu/src/render.rs)

The browser [canvas surface](../../engine/crates/sim-gpu/src/surface.rs) obtains
a compatible WebGPU adapter for the canvas before constructing its device.
It checks initial and resized backing dimensions against the device texture
limit, reports device-loss signals, and acquires frames for rendering on that
same device. A required-GPU browser smoke on Headless Chrome 154 used
`BrowserWebGpu` to construct this surface, render the committed seed, queue
a reset during a bounded advance, reject the stale reply, and render the new
epoch. Its ignored result is
`artifacts/validation/e08/browser-surface-pre-solver-2026-09-29/result.json`.
The required-GPU readback run accepted two full-size ticks, rendered their
committed frames, sampled three individual cells, captured one explicitly

`artifacts/validation/e08/browser-readback-2026-09-29/result.json`.
The later balanced-build sustained run accepted 60 full-size browser ticks;
its result is
`artifacts/validation/e08/browser-sustained-balanced-2026-09-29/result.json`.
The command was `bun web/scripts/test-browser.ts artifacts/validation/e08/browser-sustained-balanced-2026-09-29 --require-gpu --sustained-gpu`.
Runtime device-loss injection remains pending. The live sandbox still selects
its legacy Canvas 2D context.

The opt-in page at `web/gpu.html` exposes pause, resume, reset, one-cell
inspection and a bounded water/air brush. It pauses while hidden and requires

The [page controller](../../web/src/gpu-main.ts) releases the scene once on
`pagehide`. A restored back/forward cache entry reloads on a persisted
`pageshow`, so it creates a new scene instead of using released WASM state. If
Reset waits for an active probe while paused, probe completion reads the new
epoch, clears the pending marker and renders the reset scene before controls
become available again. [UI lifecycle tests](../../web/tests/app/gpu-main.test.ts)
exercise both paths with a mock session and synthetic page transition events.
They do not establish whether a real browser will retain this WebGPU page in
the back/forward cache.

The [probe](../../engine/crates/sim-gpu/src/probe.rs) maps 16 bytes for one
selected cell. Its stamp includes epoch, tick, accepted time, generation and a
revision that increments for accepted substeps and zero-time paints. The owner
rejects a probe after an intervening reset. The explicit
[capture prototype](../../engine/crates/sim-gpu/src/checkpoint.rs) maps
3,631,800 bytes of five dynamic fields for one committed generation, then
returns a 3,631,908-byte `PFCP` version-zero diagnostic record. It has no
load API and is not the durable `PFSN` recovery format planned for E13.
No normal frame or accepted step invokes this full-state capture. The browser
smoke verifies the returned length, dimensions, epoch, tick and revision.

## Continued transport correction on 5 October 2026

The live PR preview passed 300 ticks, then rejected an invalid transport cell
at tick 366. A longer required-GPU fixture now targets 3,600 completed ticks
and 60 model seconds, with checkpoints beyond ticks 125, 366 and 1,144.

Temporary GPU diagnostic records identified two distinct normal-f32 cancellation
cases. These records were removed after diagnosis; production retains its
four-byte transport status and strict invalid-cell and orphan-marker guards.

At tick 366, liquid owned mass was `0x2582b62b`. The outgoing phase equalled
the owned amount, and incoming phase `0x195ddc65` was less than half an ULP
of that inventory. Reassociation of the plain gather subtraction/addition
returned zero phase but a nonzero marker. The
[gather shader](../../engine/crates/sim-gpu/shaders/transport_gather.wgsl)
now uses explicit nested `fma` boundaries for both the small-opposing-flow
and near-exhaustion branches. An exact GPU regression covers both X and Y
transfer with the measured incoming pair and with no inflow.

The first extended run then reached tick 1,144. Its carrier outgoing phase
sum exactly equalled owned phase `0x2494cccd`, but the two outgoing marker
shares summed to `0x2c3c6a34` rather than owned marker `0x2c3c6a35`.
The remaining marker was one ULP, `2.1684043e-19`, with no retained carrier
phase. The [donor budget](../../engine/crates/sim-gpu/shaders/transport_donor_budget.wgsl)
now uses explicit `fma` boundaries for its complement and recomplement,
so both rounded operations remain in the shared two-face marker ledger.
These measured cases involve normal values, not subnormal flushing.

The diagnostic reports are
`artifacts/validation/xer-63/browser-diagnostic3600-b/result.json` and
`artifacts/validation/xer-63/browser-diagnostic1144-b/result.json`.
[WGSL floating-point rules](https://www.w3.org/TR/WGSL/#floating-point-evaluation)
permit reassociation and may expand `fma` into multiple operations. The
hardware regressions establish behavior on the tested adapters; they do not
establish a portable guarantee for every backend. The pressure, volume,
phase association and conservation gates remain unchanged.


A later 128-round candidate approached the frozen cell-volume gate. At the
rejected cell, tracked closure residual was `8.861744e-6`, with the existing
`1e-6` initial-packing allowance. The gathered f32 volume differed by
`1.0004442e-11` m3 from the `1e-6` m3 cell, just beyond the unchanged gate.
The component mean fill remained `1.0000000174`, so this was a local margin
failure. Closure now measures the difference of the same separately rounded
raw face fluxes used by transport. Its fixed budget is 256 rounds; the derived
four-face CFL reserve is `0.01024`. Each face correction remains bounded to
`1e-5` cell widths per round, and the hard face CFL cap remains `0.5`.

The larger correction budget exposed a separate density validity issue.
Normal liquid masses `0x04be3c58` and `0x04be3cf8`, about `4.4724e-36` kg,
produce subnormal physical volumes after division by the water density.
The density shader's positive-phase test could therefore reject a valid
normal mass when that intermediate volume was flushed to zero. It now
validates phase positivity in cell units, `(mass / cell_volume) / density`.
The original physical-volume finiteness and absolute closure checks remain.
No phase or marker is floored, dropped or rewritten by this density stage.
The native regression includes both measured liquid masses and the symmetric
carrier case. The diagnostic report is
`artifacts/validation/xer-63/browser-density256/result.json`.


At tick 2,195, a corrected two-outlet carrier ledger was rejected by the
donor's subtraction-based budget check. Its outgoing amounts
`0x2214f209` and `0x2494f20a` rounded to the owned phase `0x2499999a` when
added, exactly as gather consumes them. Subtracting the larger outlet from
inventory first rounded the available small outlet to `0x2214f200`, so the
alternative comparison falsely rejected that same ledger. Both preliminary
and corrected donor-phase checks now compare the rounded outgoing sum against
owned phase, matching gather and the shared marker budget. The exact case is
covered on both axes. The strict sum limit remains the owned phase, with no
extra tolerance. The diagnostic report is
`artifacts/validation/xer-63/browser-donor2195/result.json`.


The local pair correction uses relaxation `1.75` within the same fixed budget.
An uncapped exact pair update is a convex mix with weights `0.125` and `0.875`;
it preserves the pair sum and local bounds while multiplying the difference
by `-0.75`. Clipping only reduces that mixing weight. Ordered disjoint passes
therefore preserve the component sum and contract the residual norm in exact
arithmetic. This improves redistribution without adding passes or changing
the physical face correction cap. Floating-point velocity and flux rounding
still require the final measured gates; no unconditional f32 convergence
guarantee is assumed.

## Free-surface motion correction on 5 October 2026

The user observed waves beginning near tick 200 and motion that did not settle.
The original four-face velocity loop was applied only at construction or reset.
It was not a repeated source. The renderer samples committed liquid mass;
it does not add a wave animation. Passing pressure and inventory gates in the
earlier 3,600-tick record did not establish physical motion stability.

The original moving native seed had initial MAC kinetic energy
`8.000001248e-9` J. At tick 300 it reached `1.574165732e-3` J, about 196,771
times the initial energy. Its maximum column-height change reached
`0.804748` cells. A zero-velocity seed stayed exactly at rest through 300
ticks. Removing gravity made the original moving seed lose kinetic energy,
while halving the step duration did not remove the growth. These diagnostic
logs are under `artifacts/xer-63/wave-diagnostic/`; they are not acceptance
results for the final source.

The defect was in the [phase-face reconstruction](../../engine/crates/sim-gpu/shaders/transport_face.wgsl).
Each directional sweep previously inferred its own strip normal from that
direction's gradient. A small lateral variation beside a nearly horizontal
surface could therefore drain a whole thin phase through a tangential face.
The corrected CPU and GPU paths select the dominant liquid-fraction gradient
as the axis-aligned normal, with X chosen on exact ties. Tangential sweeps
carry the donor's phase proportions; normal sweeps retain the geometric strip
overlap. Shared face accounting, marker association, gravity, viscosity,
outer-clock duration, pressure gates and the iteration cap remain unchanged.
This is a bounded strip approximation, not general PLIC reconstruction.
Near ties can select different axes after f32 rounding.

The [production seed](../../engine/crates/sim-gpu/src/scene/demo.rs) now starts
and resets with zero face velocity. The exact original four-face loop remains
in the ignored native moving fixture. At ticks 50, 125, 200 and 300, its kinetic
energy must remain within 5% of the initial value. The final 300-tick run
measured `1.852776823e-9` J, a 76.8% reduction from the initial value. Its
maximum column-height change was `2.974633162e-4` cells. The rest fixture
measured exactly zero velocity and unchanged phase masses and markers through
300 ticks, including tick 200. All 38 ignored native GPU unit fixtures and
the separate native probe passed. The new transport fixture checks both axes,
both flow signs, thin-phase flux, CPU parity, conservation and marker ownership.
The final native log is `artifacts/xer-63/native-rest-orientation.log`.
All 15 focused CPU transport tests also passed; their log is
`artifacts/xer-63/wave-diagnostic/cpu-transport-final.log`.

These results use branch `codex/gpu-pressure-sustained` at `76fd43c` plus the
interface, seed, regression and documentation changes described here. Native
MAC kinetic energy uses arithmetic face density and one cell volume per
interior face, matching the CPU metric. Cell-center potential-energy
diagnostics do not reconstruct subcell phase centroids. The moving fixture
does not establish a complete mechanical-energy ledger or every possible
perturbation, geometry, adapter or later migration gate.

### Diagnostic contract and capture

The scene owns an optional bounded
[pressure journal](../../engine/crates/sim-gpu/src/pressure/journal.rs).
Diagnostics are disabled by default and make no clock reads in that state.
Enable accepts a capacity from 1 through 65,536. Records retain the prefix and
count subsequent dropped events. Candidate records identify epoch, outer tick,
candidate, attempt, committed-state revision, accepted time before the candidate
and encoded timestep. Each initialization, PCG batch and final-gate record copies
the existing eight status words with map-start and map-complete times. Word 3
contains the residual bits, word 4 the divergence bits, word 5 the completed
iteration count, word 6 the convergence flag and word 7 the invalid flag. Decode
floating values as little-endian f32 bits; raw u32 storage preserves nonfinite
status values without invalid JSON.

Candidate outcomes distinguish acceptance, numerical rejection and terminal failure.
A successful pressure final gate alone does not mean that the candidate was
published. The pressure journal adds no submissions, maps or shader dispatches.
The browser adapter requires idle enable, drain and disable operations. Drain
before disable, which clears the record; reset clears the configuration as well.

The existing API-cost profiler now retains ordered host submit, map and advance
spans and sampled shader timestamp pairs, each with advance context. Host slots
are reserved when operations start, so asynchronous completion does not reorder
the prefix. Failed runs export available pressure and host records, retain the
original run error and report any secondary export error. Timestamp collection
on that failure path has a five-second limit. Partial results cannot pass a
completed-run acceptance check.

Timestamp sampling adds query resolves and staging copies to sampled command
buffers. It maps the diagnostic samples after the timer. The final run collects
219 timestamp batches containing 302 pass pairs, or 4,832 additional diagnostic
readback bytes. These bytes are separate from the unchanged simulation readback
accounting. Diagnostic allocation and command overhead remain inside the run's
wall duration even where the profiler excludes its own storage from engine API
counts.

Profile mode uses capacity 8,192 for each host, shader and pressure track. It
exports `result.json` and `profile-trace.json`. The latter uses separate host and
shader origins and can be loaded in Chrome or Perfetto. Host and browser pressure
times share `performance.now`. GPU timestamps remain in a separate clock domain;
their apparent horizontal difference from host events is not queue delay.
Native journal timing uses a separate `Instant` domain.

Optional `--browser-trace` records the newly launched isolated Chromium through
CDP. It starts before navigation and includes initialization, warmup and the
measured work until completion or the duration limit. Categories cover DevTools
tasks, frames, user timing, V8, GPU and Dawn. The recording retains a 32 MiB prefix
and allows at most 128 MiB of JSON output. Its duration option accepts 1 through
300 seconds. Capture metadata reports loss and stopping reason. Browser tracing
adds overhead even in baseline mode; that combination is marked diagnostic.
The capture cannot attach to an existing user browsing session.
