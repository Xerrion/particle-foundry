# P1 / M1 / E01 bootstrap evidence

**Status: E01 validated on 26 September 2026. M1 and P1 are incomplete.** Next: E02's minimal port contracts after verifying signed delivery in [RESUME](../RESUME.md). This report validates bootstrap/build/lifecycle only, not a numerical reference, GPU solver, renderer or fire gate.

## Delivered scope

The four Rust crates supply validated grid geometry, a separate CPU reference-session bootstrap, a Rust-owned asynchronous wgpu device and narrow WASM initialization/disposal exports. `Engine::drop` also performs teardown, so generated `free()` does not bypass explicit GPU disposal. There are no JS-visible world arrays, CPU/GPU world mirrors or simulation steps.

The existing TypeScript application, `src/` layout, catalogue, legacy physics and Canvas renderer are unchanged. `engine-client.ts` is a thin generated-binding loader. The standard app remains legacy-only; no backend is promoted. `bun run build` generates WASM before the frontend build, while the isolated smoke build actually packages the WASM/JS under the non-root base `/engine-smoke/`. The unused experimental engine is correctly absent from the ordinary app bundle.

The user narrowed this task to the WASM/GPU port and necessary contracts/reference work. No circuit, chemistry, nuclear or catalogue expansion was added.

## Toolchain and local execution

Pins validated here: Rust **1.98.1**, wgpu **29.0.4**, wasm-bindgen library/CLI **0.2.108**, wasm-bindgen-futures **0.4.58**. Frontend: Bun **1.3.12**, TypeScript **7.0.2**, Vite **8.3.0**. Native/browser host: macOS **26.6.2**, arm64. Browser: dedicated Chrome headless shell **153.0.8010.12**, with `--enable-gpu`; native backend: Metal; browser backend: BrowserWebGpu. No adapter performance result is inferred from those names.

The default macOS 27 SDK fails with the installed linker (`unknown architecture arm64e.x1-macos`). Native and WASM host-build commands used the installed 26.5 SDK **per command**, without changing the global SDK:

```sh
SDKROOT=/Library/Developer/CommandLineTools/SDKs/MacOSX26.5.sdk cargo test --locked --workspace
SDKROOT=/Library/Developer/CommandLineTools/SDKs/MacOSX26.5.sdk bun run build
SDKROOT=/Library/Developer/CommandLineTools/SDKs/MacOSX26.5.sdk bun run check:wasm
CHROME_BIN='/Users/lasn/Library/Caches/ms-playwright/chromium_headless_shell-1243/chrome-headless-shell-mac-arm64/chrome-headless-shell' \
  bun run test:browser artifacts/validation/p1-m1/new-run --require-gpu
```

Install the pinned CLI with `cargo install wasm-bindgen-cli --version 0.2.108 --locked` and use the checked-in Rust toolchain. Generated files are ignored and must be rebuilt on a fresh checkout. The build script rejects CLI/library version mismatch; freshness checking regenerates into a temporary directory without overwriting the checked output.

CI is configured for formatting, native tests, Clippy, WASM generation/freshness, frontend checks, docs validation and the real browser fixture. **GitHub Actions has not run.** GPU initialization is optional in the default CI smoke and reports `unavailable` separately. Passing CPU bootstrap on an unavailable adapter is not a GPU pass; `--require-gpu` makes that absence fail the run.
